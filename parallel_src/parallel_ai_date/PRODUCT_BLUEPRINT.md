# Parallel — 简版产品蓝本 v0.1

## 1. 一句话定位

**用 Tinder 式刷卡认识已有作品中的角色，再用 Elsewhere 式通信、线下扮演和持续记忆经营关系的多身份 AI Dating App。** 不是现实真人配对平台。

## 2. 四栏结构

1. **我的**：创建/切换 Profile，头像、名字、性别、年龄、简介、交友目的、兴趣、择偶偏好，以及多个希望匹配的系列。当前 Profile 可以扮演自己、原创玩家角色或已存在的同人角色。
2. **发现**：左滑不感兴趣，右滑感兴趣；右上刷新一批最多十位候选。候选身份必须来自原作，照片区默认留白；点击可读取此角色的文字照片描写，不调用图像生成。AI 人物拥有自主匹配权。
3. **消息**：匹配会话、角色主动发消息、对话和多媒体（后续）；通过自然情节进入线下小说式扮演，再返回手机界面；两个模式共享同一关系记忆。
4. **终端**：API Base URL、Key、拉取模型、采样参数、文字照片描述与文字 Prompt 预设；聊天和见面两套自有条目可独立编辑、启停、排序。

## 3. 人物宇宙与版本

- AI 候选 **只能来自已有原作**，不随机创建原创 AI 人物。
- 同名角色不同原作连续性或人生阶段是平行世界主体，例如 RE2 Leon、RE6 Leon、电影版 Leon。不同主体记忆隔离。
- 同一版本人物再次出现，不是一个新副本；左滑、右滑、吵架、解除匹配、重新匹配都不清空他经历过的事情。
- 玩家 Profile 是扮演身份。一个玩家可以操控多个完全不同的人物；**不能**默认所有 Profile 是“同一个人的小号”。
- 同一 AI Leon 和多个玩家 Profile 交往时，拥有自己的共同人生和事件记忆；但当前玩家扮演身份无法直接读取其他身份的私密聊天。
- 玩家扮演的 Brian 与独立 AI Brian 的数据、记忆、对话完全隔离。Brian Profile 不能匹配同版本 AI Brian，而 Stephanie Profile 可以匹配他。
- 在故事中，AI 可以凭现实证据对不同 Profile 的相似之处产生怀疑，但不预设“他们是同一人”。

## 4. 核心流程

`创建 Profile → 选择一个或多个作品 → 刷新候选 → 左/右滑 → AI 自主决定是否 Match → 首条消息 → 持续聊天 → 自然赴约/线下小说 → 回到短信 → 分手/解除匹配 → 再次刷到同一人 → 记得上次的关系`

## 5. UI 原则

- Apple 风格：清透玻璃、柔和光影、轻量渐变和可视层次；不把所有界面做成难读的低对比度薄白字。
- 图标用矢量 SVG，避免 Emoji 作为功能图标。
- 滑动卡片以空白照片位置、姓名年龄、原作时期、生活化简介为主；**人物公开的个人资料不等于所有原作秘密**。
- 手机聊天只出现实际消息气泡；面对面小说可以描述环境、动作、眼神和情绪。

## 6. Prompt 规则

- 全局核心硬规则 + 原作身份与时间线 + AI 自身事件记忆 + 当前玩家 Profile + 当前两人共同聊天历史 + 本模式预设 + 本轮输入。
- 禁止让手机消息套用面对面小说 Prompt。不同模式、不同预设应该可切换/覆盖，而不是训练成单一固定文风。
- 模型需知晓人物曾经与其他身份发生过的真实经历，但不能因为同一个本机使用者就推断这些身份是同一人。
- 后续完善自有 Prompt 条目编排、人物来源核验、长期记忆与人物关系管理，不集成受限第三方专用预设；允许兼容开发者自行创作并持有的 Elsewhere 预设格式。

## 7. 交付现状

v0.5 提供单文件 HTML 与本地 Web App + SQLite + 已收录角色目录 + OpenAI-compatible 文字 API + 自有预设兼容 + 60 秒静默合批，取消图像 API 入口。详情、运行说明和不足见 README。


## v0.2 修正：消息窗口内原地切换模式

- 每个角色的消息窗口顶部拥有手动「进入见面 / 返回聊天」矢量按钮。不跳转新页面，不改变其他聊天窗口。
- 点击只决定此角色这条关系的**下一条输出格式**。手机消息继续使用气泡；见面使用同一会话时间线的小说段落。过去生成的消息不被整体重新渲染成新模式。
- 支持先发送最后一条消息、再切换模式、再点「让角色继续回复」，直接以新模式生成下一轮。不要求用户为切换模式再输入一句废话。
- 聊天和见面各有独立 Prompt 条目，事件、历史、角色记忆保持同一份。手动开关优先，不靠关键字强制自动切换。
- 易用性：先交付可直接双击打开的单文件 HTML；浏览器直连 API 可能受 CORS 限制。保留本地服务端备用，不要求普通用户先操作 `.command`。

## 作品来源与预设的产品边界（v0.3）

- 用户必须能自由输入作品标题并按回车生成 Tag，支持多选和删除，而不是在预置作品按钮中选择。
- 未收录作品的 Tag 可以保存，当前不冒充已经知道该作品的角色清单；未来通过可核验来源扩充目录。
- Prompt 体系为本项目独立创作的文本条目：手机聊天和面对面见面各有自己的编辑、启停、排序与执行路径；不引入第三方受限预设及其转换代码。

- 自有 Prompt 条目支持独立 JSON 导入与导出（`parallel-text-preset` v1），可追加或替换涉及模式；与第三方受限预设无关。

## v0.5 已实现

- 发现页照片位留白，点击查看纯文字模拟照片描写，另可由文本模型主动扩写；不主动调用 AI 生图。
- 每条新短信启动/刷新 60 秒静默窗口；合批只请求一次，模式切换保留短信但取消挂起的手机回复。
- 自有 `elsewhere-preset` v1 JSON 可只导入面对面模式，保留条目排序、角色、启停；运行时展开 `{{user}}` / `{{char}}`，原始 JSON 不被改写。
- 手机聊天与面对面继续单独导出为 Parallel 格式 JSON，见面按钮和混合历史显示保留。
