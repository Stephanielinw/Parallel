# Parallel Maintenance M05 · 统一事件时间线：事实权威与幻觉审计

## 用户真实事故（2026-11-22）

Carlos 与玩家约好 17:30 相见，但玩家因忙没有赴约。旧监控推演自动描述 17:30 已经共同见面、吃饭、回家。玩家晚上才回家时 Carlos 的实际 SMS 说自己在门口，但一打开见面模式却跳到室内/家里。

这是**预测被误当共同经历**的权限漏洞，不是简单换个地点文案就能解决。

## 事实来源优先级

1. 实际发生的玩家互动与已保存的见面场景原文。玩家自己的动作必须由玩家决定。
2. 角色最近带时间戳、非撤回的直接位置陈述。它决定角色声称身处哪里，但不是玩家已经到场或共同活动的证据。
3. 双方确认的预约（具有可能性，但未发生；没有赴约的真实证据时不得判定见到了面）。
4. 监控的角色独立生活计划与 AI 生成的行程：**始终是推演，不因当前时钟经过安排时间而自动升级成事实**。

切换「面对面」模式只创建**候场场景**，不是双方已经接触。仅当玩家在现场行动，或角色在存档现场原文中有实际完成的空间移动，才更新场景。监控必须向互动让步，而不是反过来驱使互动。

## 改动范围

- 离线 JS 与 Python 服务端均按**最近 SMS 角色位置 / 用户明确到达证据**选择首次开场地点。没有明确当前位置时，最后才参考未被取消的**聊天约定地点**；不再从监控读取兜底。若没有地点证据就写「见面地点待确认」，避免乱传送。
- Python 开场 Prompt 从「刚刚线下碰面」改为**只描写角色候场，用户自行决定如何接触**，与此前离线端规则一致。两个后端的场景开始事件都标识为**候场，接触待确认**。
- 老的 `schedule` 监控行无论当前钟表是否已到，读取时均打上 `is_planned:true`。如果内容含双方一起行动、玩家名称加共同活动动词等，**临时向用户及 AI 隐藏臆造的地点与活动**，显示「约定待核实 / 双方是否见面未知」。该处理只在读取时生效，不去改写旧版存档记录；角色独立日程可以继续参考。
- **候场不等于接触**：只有角色 AI 开场文字、没有玩家任何真实现场回合时，保留原始候场卡片与文字，但禁止新建一条「双方亲历见面」记忆；历史已生成的候场假记忆不自动删除，但也不得通过检索进入聊天事实。这样的空候场结束时不应被同步成双方真实见面的监控足迹或触发共同活动重排。
- **Python 日记还原事实层级**：此前日记模板把推演的上午、下午、傍晚行程写成「已经完成」「已经去了」，这是另一处幻觉入口；改成明确「原计划、推演、实际成行未确认」，监控足迹添加已确认/未核实提示。只有真正出现玩家现场回合的见面才可用于日记中的「见过面」叙述。
- 从聊天 Prompt 中去掉模型自行撰写的 **过去见面总结正文**，保留原始见面时间索引、现场末尾消息节选，以及按需细节检索。
- 对 `meeting_summary`、`episode-summary`、`daily-summary` 等模型归档，先核对该 Profile + 角色的关联消息 ID 确实存在、没有撤回；见面归档还须存在所属见面记录。**只有原始消息摘录会被塞回聊天 Prompt**，生成摘要继续保留在已有存档/记忆卡片中但不再被模型当作已证实的共同经历。用户手动更正与自写记忆不自动改写或清理。
- 全局模型系统指令明确「对话文字不是其中计划成行的证明；监控推演不是双方共同回忆；模型摘要只用于定位，不能背书不存在的对白」。

## 验收

- `tests/m05-event-authority.test.cjs` 通过合成无赴约 / Carlos 门口 SMS / 旧监控已一起吃饭回家 / 假记忆摘要复现；验证不改真实存档，保留原文，原始消息能检索到、原始摘要不作为事实注入。
- `parallel_src/parallel_ai_date/tests/test_m05_fact_authority.py` 验证 Python 同源算法、仅候场、不把旧监控当现场，归档标记和角色 ID/Profile 隔离。
- 所有 M00–M04 回归与移动端尺寸 WebKit 测试通过后才允许合并，之后核验 GitHub Pages。
- 测试只用虚构 Profile 和隔离的聊天内容；没有访问用户真实 iPhone 存档，也不做 M04 尚未批准的迁移。

## 剩余的风险（不能声称已全面消灭 LLM 幻觉）

1. 现有情节归档模型仍可能从原始对话中生成**没有证据的摘要文案**；本 PR 阻止它以权威事实**回流聊天 Prompt**，并不自动纠正用户已保存的旧记忆卡片。记忆卡片里出现错误，可以使用「纠正/标记存疑」功能。
2. 角色的主动聊天输出仍由第三方 LLM 生成。即使提示词明确约束，模型仍可能现场编造对白；除非进一步实现基于源 ID 的逐条证据校验，无法保证 0 幻觉。
3. 旧格式时间线没有统一的持久化 **observed / planned / inferred** 事件类型及回放机制。此 PR 用现有 `source` 与 `is_planned` 在读取时确定权威，不进行有丢失风险的全量 schema 迁移。
4. 角色自述是**角色声明**，也可能不准确。系统不应把它证明为真实位置或两人已经接触。新版本用它决定开场候场地点，但给玩家现场修正权。
5. 同步旧 `localStorage` 保存和照片独立 IDB 的历史风险属于未完成的 M04 迁移门槛，M05 不擅自触碰。

**结论**：M05 本轮最小闭环优先阻断「计划 → 共同事实」和「模型摘要 → 亲历证据」两条污染路径。真实反馈与日志若复现其他无依据的回忆，还需要针对对应生成源设计更精确的检验；不能掩盖模型能力边界。
