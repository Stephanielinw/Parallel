# Parallel Maintenance — M03 · 存档只读核验（存储迁移前安全门）

> **M03-A 的范围**：只增加对已经导出的 JSON 的只读检查、两份文件的 SHA-256 比对和自动化回归测试。此版本 **不迁移存储、不覆盖现有存档、不读取或更改手机里尚未导出的私密数据、不清理任何 localStorage/IndexedDB**。M00 代码恢复分支 `archive/m00-baseline-20261122` 保留。

## 发现与目的

目前正式网页主存档保存在 `localStorage['parallel-portable-v2']`（可压缩），聊天真实照片在独立 IndexedDB。导出菜单已有包含照片的 JSON 与只含文字的 JSON，旧恢复入口会覆盖当前存档。

M00/M02 的测试只证明**合成存档**在模拟环境中能够保存和恢复，不等于你的 iPhone 已经有两份真实备份。因此，M03-A 首先让用户能检查实际导出的文件，同时保留现有导出/恢复功能。

## 新增只读功能

在 **终端 → 连接与模型 → 存档备份** 处，先点「导出完整存档 JSON」，确认文件确实存入 iOS「文件」App。再将**同一份导出的 JSON 文件**复制到两个不同且可信的位置，并通过「只读核验两份备份」选择一份或两份 JSON 文件。

- 逐个解析所选文件；确认版本/必需字段、Profile/短信/见面/记忆/日记/监控日期数量；
- 检查是否存在重复消息 ID、见面来源缺失、相片引用不全或无效 JPEG 数据字段；
- 拒绝包含非空 API 密钥和 `systemLogs` 的非安全备份；
- 有两份时对**原始文件字节**分别计算 SHA-256，并比较是否完全一致。两份若是**不同时间重新导出**，`createdAt` 可能不同；即使记录一样，哈希不同也属预期。正确步骤是导出一次、**复制同一个文件**；
- 文件只在当前浏览器处理，不进行网络上传、不执行 `importData`、不触发游戏主存档写入；
- 显示不确定性和明确警告。通过格式检查不代表所有旧资料均来自完整原始存档，也不代表照片经过图像解码测试。

**不要**将「仅文字备份」当成包含真实照片的完整备份。若曾上传真实照片，核验结果中应看到照片引用数与附件数相等；否则请重新导出完整存档。

## 与手机实际备份有关的限制

1. SHA-256 相同说明两个选中的文件字节内容一致，但不证明它们真的保存在**两个相互独立的存储位置**；请自行检查「文件」里的位置。两个名字不同但放在同一个云盘的文件仍面临同一个云盘失效风险。
2. 结构核验**不能保证**手机当前活跃记录已全部写入存档；它只能证明被选中的备份文件结构合理。用户可对比真实 Profile / 会话 / 见面 / 日记数量。
3. Linux Playwright WebKit 不是真实 iPhone Safari/PWA；iOS 存储被回收、系统杀后台、分享保存中断等仍需真机验证。
4. 此次**不执行恢复操作**。恢复是覆盖而非合并，必须先独立备份和明确确认。
5. 对 100 MB 以上的文件不执行本次核验；每次最多选择两个文件，避免在手机上一次读取大量敏感内容。

## 自动化验收

- `tests/m03-readonly-backup-audit.test.cjs` 检查 JSON 字段、Unicode、照片引用/附件、重复 ID、遗漏的见面来源、安全凭据与未修改原始 JSON。
- `e2e/m03-backup-preflight.spec.ts` 在实际 WebKit 里操作终端文件选择：两份相同的合成 JSON 哈希一致，私密消息文本没有进入报告，坏文件明确失败，主存档在操作前后相同。
- 上述两套测试均接入现有 GitHub Actions 发布前门禁；M01 的 18 条契约与 M02 生命周期、日记/监控测试照常执行。
- 不向外部 API 发送任何测试内容，不需要付费模型。

## 下一阶段禁止越过的门槛

正式 IndexedDB 主存档迁移（包括迁移、删除、替换 `localStorage`）属于 **M03-B 或后续单独维护任务**，当前不会执行。先需：(a) 用户在 iPhone 上实际导出并在不同安全位置保存两份、核验完成，(b) 在隔离环境中证明旧、新存储版本可逆并保留照片与原文，(c) WebKit 与真机恢复/异常中断验证，(d) 明确批准正式切换。

**M00 代码恢复点不是玩家数据备份。**
